## 1. Введение

Веха 3 в курсе — инфраструктура: архитектура репозитория и качество кода (включая README); воспроизводимость прогонов и логирование артефактов. Сеть та же, что в baseline: YOLOv8s-pose. Здесь я фиксирую, как её запускать и сравнивать.

Ориентир по работам курса — связка Git + конфиги Hydra + логи (W&B) + версия данных (DVC) + Docker + тесты. Это я и собрал. Lightning вокруг Ultralytics не оборачивал: обучение уже идёт через их trainer, отдельный LightningModule ничего не добавил бы.

## 2. Архитектура репозитория

| Слой | Роль |
|---|---|
| Данные | Waymo parquet → срез сегмента → формат YOLO-pose |
| Модель | YOLO-pose: полный кадр или поза по GT-кропу |
| Метрики | OKS, PCK@0.2, матчинг людей, COCO-17 ↔ Waymo-14 |
| Конфиг | Hydra: модель, вход, порог, протокол, seed |
| Запуск | eval / train CLI; сетка без новой тетрадки |
| Логи | `runs/` + Weights & Biases |
| Данные (версия) | DVC-указатель на zip среза ГП2 |
| Качество | pytest, ruff, GitHub Actions, Docker |

Ноутбук на Kaggle только поднимает GPU. Протокол совпадает с CLI.

README описывает venv, Docker, DVC, eval/train и дерево проекта. Конфиги — в `configs/README.md`, срезы — в `data/README.md`.

## 3. Воспроизводимость

**Seed** 42: Python, NumPy, CUDA.

**Hydra.** Меняются модель nano/small, вход, порог, протокол, число кадров. Сетка — несколько конфигов подряд.

**Данные.** Baseline привязан к одному сегменту Perception и 40 кадрам. Полный Waymo (сотни GB) в DVC не вешаю. В git лежит указатель DVC на zip среза ГП2 (хеш и размер); сами jpeg — локально или `dvc pull`. Сплит для дообучения — хвост того же ролика по времени.

**Docker.** Образ ставит пакет и гоняет pytest/ruff без GPU и без картинок. Так проверяется код на машине без CUDA.

**CI.** На push: lint и тесты.

Повтор якоря ГП2: YOLOv8s-pose, вход 1280, порог 0.35, 40 кадров, оба протокола оценки.

## 4. Логирование артефактов

В каждом прогоне: метрики (OKS, PCK, попадания, пропуски, latency), копия конфига, при обучении — лучшие веса.

Kaggle после сессии стирает диск, поэтому скаляры дублируются в W&B, проект `pose-av`. Без ключа оценка не падает. MLflow опционален.

В git нет весов YOLO, jpeg и parquet.

## 5. Качество кода

Тесты метрик, матчинга, формата разметки и записи лога — без датасета и без GPU. Зависимости с верхней границей версий. Опционально: wandb, dvc, ruff.

Нет PyTorch Lightning: это был бы декоратор над чужим trainer. Нет DVC на полном Perception — только на срезе, на котором считался baseline.

## 6. Вывод

Репозиторий можно клонировать, прогнать тесты в Docker или CI, повторить eval через Hydra и найти цифры в W&B. Это закрывает инфраструктуру. Скор выше COCO — уже веха 4, и упирается в объём сцен, не в отсутствие конфигов.
